# 安全

Pi 是一个本地 coding agent。它以启动它的用户账户的权限运行，并将该用户可写的文件视为同一本地信任边界内的内容。

## 项目信任

项目信任控制 pi 是否加载项目本地的设置、资源、包和扩展。它不是沙箱，也不会限制模型在你开始在某目录工作后要求工具执行的操作。

当 pi 在当前工作目录中发现以下任一内容时，会认为该项目包含需要信任的资源：

- `.pi/settings.json`
- `.pi/extensions`、`.pi/skills`、`.pi/prompts` 或 `.pi/themes`
- `.pi/SYSTEM.md` 或 `.pi/APPEND_SYSTEM.md`
- 当前目录或其祖先目录中的项目 `.agents/skills`

仅有一个空的 `.pi` 目录不算需要信任的项目资源。

当交互式会话在包含需要信任的资源的项目中启动，且当前目录或其父目录没有已保存的决策时，pi 遵循全局设置中的 `defaultProjectTrust`。默认值为 `"ask"`，即在 UI 可用时询问是否信任该项目。已保存的决策按规范目录存储在 `~/.pi/agent/trust.json` 中，应用于当前路径或父路径的最近的已保存决策优先于全局默认值。

信任项目后，pi 可以加载需要信任的项目资源，包括：

- `.pi/settings.json`
- `.pi` 资源，如扩展、技能、提示词模板、主题和系统提示词文件
- 通过项目设置配置的缺失项目包
- 项目本地扩展和项目包管理的扩展

拒绝信任会跳过受保护的资源。除非上下文加载被禁用，否则 `AGENTS.md` 和 `CLAUDE.md` 上下文文件无论项目信任与否都会被加载。在信任确定之前，pi 只加载上下文文件、用户/全局扩展和 CLI `-e` 扩展。用户/全局扩展和 CLI 扩展可以处理 `project_trust` 事件；第一个返回是/否决策的扩展拥有该决策权。

非交互模式（`-p`、`--mode json` 和 `--mode rpc`）不显示信任提示。在没有适用的已保存信任决策的情况下，`defaultProjectTrust: "ask"` 和 `"never"` 会忽略此类资源，而 `"always"` 会信任它们。使用 `--approve`/`-a` 或 `--no-approve`/`-na` 可为单次运行覆盖项目信任。

## 无内置沙箱

Pi 不包含内置沙箱。内置工具可以读取文件、写入文件、编辑文件，并以 pi 进程的权限运行 shell 命令。扩展是以相同权限运行的 TypeScript 模块。包安装、shell 命令、语言服务器、测试命令以及其他开发者工具都像普通的本地进程一样运行。

这是有意为之。Pi 被设计为在本地源码树上运行、调用项目工具链并与用户现有的开发环境集成。进程内的部分沙箱很容易被误认为是安全边界，同时仍依赖宿主机的 shell、文件系统、包管理器、凭据和扩展代码。真正的隔离需要来自操作系统或虚拟化/容器边界。

项目信任只是一个输入加载守卫。它防止仓库在你批准之前静默更改 pi 的设置或扩展。它并不会让不受信任的代码、不受信任的提示词或不受信任的模型输出变得安全。来自仓库文件、注释、文档、上下文文件或构建输出的提示注入属于预期的本地 agent 风险，pi 无法可靠地防止。

## 运行不受信任或无人监控的工作

对于不受信任的仓库、你不打算密切监控的生成代码或无人值守的自动化，请在受控环境中运行 pi。使用仅包含任务所需文件和凭据的容器、VM、micro-VM、远程沙箱或策略受控沙箱。

常见模式在[容器化](containerization.md)中有文档说明：

- 在容器/沙箱内运行整个 `pi` 进程
- 运行宿主 pi，同时将内置工具执行路由到 Gondolin micro-VM
- 仅挂载 agent 应访问的工作区路径
- 除非容器需要访问宿主会话、设置和凭据，否则避免挂载宿主的 `~/.pi/agent`
- 传入所需的最少 API 密钥或使用短期凭据
- 当任务不需要网络时限制网络访问
- 在将结果复制回受信任系统之前审查 diff 和输出

如果你以读写方式绑定挂载宿主工作区，容器或 VM 内部的写入仍然可以修改宿主文件。当需要更强地防止意外写入时，请使用只读挂载或将文件复制进出沙箱。

## 报告安全问题

要报告安全问题，请遵循仓库的[安全策略](https://github.com/earendil-works/pi-mono/blob/main/SECURITY.md)。对于安全敏感的报告，请勿发布公开 issue。

预期的本地 agent 行为、缺少内置沙箱、来自不受信任内容的提示注入以及用户安装的扩展或技能的行为，通常都不在安全边界之内，除非报告演示了真实的权限边界绕过，或表明 pi 授予了本地用户原本没有的访问权限。
